# 开启注册和曲目评论

前端已经接入现有的 Supabase 项目 `skneweesbyybsuggsvyw`。数据库管理操作需要项目所有者权限，网页的 publishable key 不能执行迁移。

## 1. 建立评论表

在这个项目的 **SQL Editor** 新建查询。全新项目按顺序运行这四份脚本：

1. [`202611160001_listening_comments.sql`](../supabase/migrations/202611160001_listening_comments.sql)：创建基础评论表。
2. [`202611160002_threads_and_avatars.sql`](../supabase/migrations/202611160002_threads_and_avatars.sql)：取消 15 秒发言限制，并启用楼中楼和音符头像。
3. [`202611160003_private_progress_and_favorites.sql`](../supabase/migrations/202611160003_private_progress_and_favorites.sql)：将原有进度限制为管理员读取，并为每个账号建立独立收藏夹。
4. [`202611160004_invites_and_introduction.sql`](../supabase/migrations/202611160004_invites_and_introduction.sql)：启用一次性邀请码和管理员可编辑的网站介绍。

管理员登录后，将鼠标移到头像上，选择“网站设置”。页面列出邀请码及使用状态，也可以点击“生成 10 个邀请码”；通过私密渠道把一个未使用的邀请码发给一位新用户。注册成功后邀请码自动作废。网站设置中可分别编辑中文和英文介绍。

已经运行过前两份脚本的项目，只需运行第三份。第二、第三份可重复执行，保留已有评论、进度和历史备注。第一份是历史版本；如果重新运行，必须再运行第二、第三份，否则会重新启用旧的限频规则。

评论表、索引、提交触发器和 RLS 规则提供以下行为：

- 所有人可以阅读评论；只有已登录的用户可以发布。
- 曲目编号必须为 1–160，评论正文为 1–2000 字。
- 作者 ID 由数据库从登录会话获取，公开昵称从注册时填写的用户资料获取。客户端不能冒充其他作者或指定评论时间。
- 用户只能删除自己的评论，不能修改其他人的内容。
- 评论没有 15 秒等待时间。管理员可在 Supabase Dashboard 管理违规内容。
- 一个主评论可以有多条回复；回复只能属于同一首作品和同一个讨论。删除主评论后，其回复会保留并变为独立评论。
- 新用户注册时自动分配音符头像；用户更换头像或昵称后，已有评论也显示新资料。修改权限由 Supabase Auth 的登录会话控制。
- 原有三态进度只能由管理员读取和修改。每位登录用户只能查看、增删自己的收藏。
- 备注界面已移除；历史备注数据保留在受保护的进度表中，普通状态修改不会覆盖它们。
- 评论表不会存储或公开邮箱。昵称与评论内容对所有访问者可见。

如果此前已经自行建立过同名表，先核对它的结构和已有策略，再执行迁移；这份脚本不会删除已有评论。

## 2. 开启邮箱注册

在 **Authentication → Sign In / Providers**（界面也可能称 **Providers**）中启用 **Email**，并允许新用户注册（**Allow new users to sign up**）。建议保留确认邮箱选项。测试邮件发送受到 Supabase 邮件配额限制；面向真实用户开放时，按项目需求配置自己的 SMTP。

在 **Authentication → URL Configuration** 配置：

- **Site URL**：`https://zchang592.github.io/qelisteninglist/`
- **Redirect URLs**：`https://zchang592.github.io/qelisteninglist/`
- 本地开发可另加 `http://127.0.0.1:8765/` 和 `http://localhost:8765/`。

无需把 service-role key、数据库密码或其他管理密钥放进 HTML、GitHub Pages 或聊天中。

## 3. 验证真实流程

1. 打开线上页面，选择“登录 / 注册 → 创建账号”，填写昵称、邮箱和密码。
2. 收到确认邮件后打开其中链接，确认返回本站。
3. 登录后打开任意曲目的“讨论”，发布一条评论。刷新页面，重新打开同一曲目，确认评论仍在。
4. 在未登录窗口查看同一曲目，应能阅读评论，但不能发言或删除。
5. 使用另一个账号验证不能删除第一位用户的评论；原作者可以删除自己的评论。
6. 确认普通账号无法读取或修改管理员进度；已有管理员可以从头像菜单打开“整理进度”并继续修改原有状态。
7. 连续发布两条评论；在另一条评论下回复并回复楼内的某个人，确认回复留在同一楼。切换头像和昵称后刷新，确认已有评论也显示新资料。
8. 用两个账号分别收藏不同曲目，确认各自的收藏夹只显示自己的曲目，刷新页面后收藏仍在。

如果弹窗提示“评论服务尚未启用”，请确认迁移在正确的项目运行成功。如果登录正常但评论发布失败，请检查浏览器返回的错误、数据库权限规则和项目状态。

## 4. 云环境访问

真实联调需要云环境允许访问：

- `skneweesbyybsuggsvyw.supabase.co`：账户、进度、评论 API。
- `itunes.apple.com`：录音片段查询；`*.mzstatic.com`：实际音频片段（由平台返回具体子域名）。
- `zchang592.github.io`：核对线上页面。
- `www.youtube.com`、`music.163.com`：核对外部曲目搜索。

环境配置草稿的保存与应用、发布是不同步骤。浏览器测试会替换这些外部响应，因此通过测试不代表线上数据库已经启用。
